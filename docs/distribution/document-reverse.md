# Document primary-body reverse materialization

An independent Knowledge installation now exposes:

```sh
python -m knowledge_platform.distribution.document_reverse \
  --source-snapshot /absolute/offline/legacy.sqlite3 \
  --target-before /absolute/offline/imported.sqlite3 \
  --target-after /absolute/frozen-export/normalized/catalog/catalog.sqlite3 \
  --body-root /absolute/frozen-export/raw \
  --bindings /absolute/private/current-document-bindings.json \
  --source-revision legacy-1 --output /absolute/new/private/candidate
```

Bindings are a private JSON object mapping every current document Asset ID to one
portable relative body path under body-root. IDs come from the current Catalog;
paths must be explicit. File size and SHA-256 must match the current Catalog's
content digest and revision. All inputs are offline snapshots; live authority
must be suspended and export obtained separately. Inspection and final input
commitments use the same database hashes. Source SQLite files are byte-read into
private copies rather than opened in place.

The tool materializes primary bodies into private `bodies/<digest>.<extension>`
files and produces an actual old-schema `catalog.sqlite3`. Existing document
rows retain nonprojected source fields; content digest, size and storage_path
bind the new files. New native document Asset IDs receive deterministic bounded
legacy IDs recorded in `identity_map`. Old source URI/provenance is validated
before the new path-derived digest is substituted. Current URI, dataset native
membership commitment and every supported logical field are checked before
normalizing identity references for the old-schema forward roundtrip.

Old source snapshots still prove the complete original core forward projection.
Core metadata reversal preserves raw unchanged cells and nested original secret
values, checks legacy widths, rejects unsupported fields/domains and validates
all legacy foreign keys without deleting unrelated records. New documents have
no inherited connector/source-item references and empty publish_targets; this
neither republishes content nor authorizes a new connector writer.

Output manifest binds input paths/hashes, body hashes, absolute output identity,
source revision, body paths, native-to-legacy IDs and the resulting Catalog.
Copying state supports exact retry after interruption, including SIGKILL after
body publication or Catalog publication. An interrupted Catalog is adopted only
when regenerated bytes match. Completed missing or altered files reject without
repair. Unknown output entries and unsafe links reject. Private interrupted
`.reverse-work-*` directories are retained diagnostically and are not committed
candidate data. Source and output are rechecked before final manifest publication.

This is `verified_inactive_documents`. The candidate's absolute storage paths
make its primary documents readable in this exact directory; moving it requires
an audited path-rebinding step. It is not a complete relocated Claw Home. Existing
secondary attachment/image/chunk references and vector/search indices are not
rebuilt. Wiki, other Catalog domains, credential continuity, unified installation
revision and audited thaw remain open. Primary body preservation is not evidence
that external/secondary references still work. `indexes_rebuilt`,
`installation_path_rebound`, activation and rollback completion stay false.

The cooperative offline/POSIX contract, existing SQLite schema restrictions and
64 MiB/file and 512 MiB body limits apply. The command requires all current
primary document bindings; it does not infer paths from URI strings or discover
credentials. Receipt contains IDs/counts/digests, not document bodies or secret
values. Exact-output retry requires unchanged input snapshots and output path.
